# JevRouter — TypeSafe Jev 驱动多模型智能路由（融合版 · 变更提案 / proposal）

- **变更 ID**：`jev-router-fusion`
- **状态**：Draft（待评审冻结）
- **版本**：v1.0
- **融合来源**：综合评审 `jevrouter-wb`（经验闭环数学理论）、`jevrouter_ch`（真实 Jev 契约与治理严谨性）、`jevrouter-cc`（生产级工程骨架与选型算法）三套 SSD 后的融合版本
- **规范词**：SHALL / MUST 表示强制，MUST NOT 表示禁止，SHOULD 表示建议，MAY 表示可选

## 1. Why —— 为什么做

### 1.1 三个必须解决的问题

| # | 问题 | 现状证据 |
| --- | --- | --- |
| **P1 模型成本日益突出** | 全部 prompt 无差别地打到最贵的旗舰模型上，而大量请求（结构化抽取、轻量改写、简单分类）用不到旗舰能力。参考 Demo 中 6 个模型的定价跨度为 `priceIn 0.28 → 3.20` 美元/百万 token（**11.4 倍**）、`priceOut 1.10 → 12.00`（**10.9 倍**）。选错模型的成本代价远大于选错带来的质量收益。 | Demo `MODELS` 目录 |
| **P2 场景与模型能力错配** | 6 个能力维度（`code` / `math` / `creative` / `reasoning` / `vision` / `longCtx`）在模型间分布显著不均。能力画像与任务特征的错配是系统性浪费。 | 同上 |
| **P3 决策经验未回流** | 每一轮「哪个 prompt 该用哪个模型」的判断都是一次性消耗。历史记录仅保存**展示态**快照，既无结果确认回填通道，更**没有任何机制把已积累经验用于后续决策**——档案只被保存与展示，下一次决策仍从零开始。 | 无任何先验修正 / 阈值标定产物被读回决策路径 |

### 1.2 融合动机（为什么需要三版合一）

单版方案各自存在无法回避的短板，融合旨在互补：

| 来源 | 提供的最优实践 | 单版短板 |
| --- | --- | --- |
| `wb` | 经验闭环五段位、贝叶斯伪计数收缩先验、ECE 校准、时效衰减、原子回滚 | 正常路径采用本地确定性重实现，未真实调用 Jev |
| `ch` | 真实 Jev 契约铁律、Jev 推荐与 Selector 硬约束权责解耦 | 篇幅过简，特征工程与经验数学空白 |
| `cc` | 真实 API + 五问并行 fan-out、8 步硬约束流水线、稳健决胜、事件流驱动 3D | 经验沉淀停留在日志检索，闭环深度不足 |

**融合目标**：形成一套既具备**真实 System One 驱动能力**，又具备**数学级安全、可自愈演进的经验闭环**，且**工程可落地**的规范。

### 1.3 可度量的目标

| # | 目标 | 度量方式 | 基线 | 目标 |
| --- | --- | --- | --- | --- |
| G1 | **成本可归因** | 单次路由成本估算与「一律走旗舰」对比 | 仅展示本次成本 | 每条档案含 `cost` 与 `costBaseline`，可算节省率 |
| G2 | **场景化选型** | 示例 prompt 选中模型分布覆盖度 | 覆盖 6/6 | 保持 6/6 且每类意图命中能力最优模型 |
| G3 | **决策可解释且真实** | 类型化答案 + 置信度 + 打分明细可复现；决策来源可审计 | 已有三档 | 补「名次序 / 目录序」双序契约 + `decisionSource` 审计 |
| G4 | **经验可沉淀且可回流** | ① 档案字段完整率；② 结果确认回写闭环；③ **经验是否改变了下一次决策**；④ **应用效果是否自动校验并可回滚** | 零回流（开环） | 五段位全备（沉淀/统计/建议/应用/校验回滚） |
| G5 | **过程可感知** | 3D 调用过程阶段化可见性 | 七阶段确定性时间线 | 保持 + 真实事件流驱动 + 输入框内联结果 |
| G6 | **不确定性诚实** | 低置信显式转人工 | 已有（< 0.60 落模糊地带） | 保持并升为硬约束 |

### 1.4 非目标（明确排除）

- **不追求「替代人工决策」**：Jev 的类型安全只约束输出形状，不保证语义正确。低置信场景一律转人工，不自动执行。
- **不做通用聊天 / 长文写作 / 代码生成**：Jev 不生成文本，路由目标模型负责生成。本系统只做「选谁来做」。
- **不引入模型微调或训练**：选型依据为静态能力画像 + 运行时负载 + 类型化问答结果 + **有界经验先验偏置**。
- **不追求「经验自动取代画像」**：经验只做**有界偏置**（`|Δraw| ≤ EXP_CORR_MAX`），不得反推或改写模型能力画像；否则退化为「永远选历史胜率最高的模型」，丧失探索能力。
- **不做在线学习 / 强化学习**：经验回流是**离线统计 + 人工批准 + 版本化应用**，不做梯度更新、不做自动探索策略。
- **不承诺经验闭环在演示期产生可观测改进**：样本积累依赖真实使用；演示期以合成数据集验证机制正确性，而非宣称效果提升。
- **不承诺跨浏览器实测**：Firefox / Safari / Edge 仅做标准 API 推导。
- **TypeSafe Jev 之外的组织级权限、计费结算与合同管理**不在本系统范围。

### 2.2 核心能力增量

1. **真实 Jev 驱动的决策运行时**（`JEV` + `CONSTRAIN` + `SCORE`）：正常路径强制经 `TypeSafeJevAdapter → System One`；五问并行 fan-out；Schema 校验守卫；8 步硬约束过滤；稳健软评分与决胜；三档输出 `ROUTE / GATE / ESCALATE`（见 §2.3）。
2. **经验回流闭环**（`ARCHIVE` + `EXP`）：把已确认经验折算为**有界、收缩、可复现、可回滚**的先验偏置，注入打分 `raw` 分。
3. **事件流驱动的过程可视化**（`TREE` + `ANIM` + `RESULT`）：3D 严格消费真实事件，不得自行推断。
4. **双形态交付**（`ARCH` + `API`）：云原生前后端分离为生产主形态；离线单文件为降级演示形态；**经验回流算法两种形态共用同一份纯逻辑层代码**。
5. **Jev 工程纪律**（`JEV`）：三层权责分层（GENERATE / DECIDE / ENFORCE）；决策契约 8 字段 + 独立版本化；三原语防误用规则；状态工程 6 段；后果分级阈值；决策凭据（见 §2.4）。

### 2.3 Decision Runtime（决策运行时）规范模型

本系统遵循 TypeSafe Jev 的 **Decision Runtime** 模型，主链为：

```
STATE →（CHOICE / SCORE / NOUL）→ JEV（System One）→ PROBABILITY →（ROUTE / GATE / ESCALATE）
```

| 环节 | 含义 | 对应需求 |
| --- | --- | --- |
| **STATE** | 决策输入状态：facts · context · evidence | `INGEST-6` `JEV-4` |
| **CHOICE / SCORE / NOUL** | 三原语问题：选项判定 / 分级判定 / 是否概率 | `JEV-2` `JEV-3` |
| **JEV（System One）** | 类型化并行决策中枢 | `JEV-1` |
| **PROBABILITY** | 类型化 · 并行 · 校准的概率输出 | `JEV-5` |
| **ROUTE / GATE / ESCALATE** | 三档处置：直接路由 / 门控观察 / 升级人工 | `JEV-5` `CONSTRAIN-*` |

**三档语义对齐**（PROBABILITY → 处置）：

| 档位 | 置信度 | 处置动作 | 语义 |
| --- | --- | --- | --- |
| 高置信 | `conf ≥ 0.82` | **ROUTE** | 直接路由执行 |
| 中置信 | `0.60 ≤ conf < 0.82` | **GATE** | 门控观察，路由并标记待核 |
| 低置信 | `conf < 0.60` | **ESCALATE** | 升级人工复核，不自动执行 |

> **关键澄清**：GATE 与 ESCALATE 是**决策运行时的输出档位**，与 Selector 的「硬约束过滤」是**两个正交层次**——前者由 Jev 置信度决定「处置方式」，后者由治理策略决定「谁能被选」。二者 MUST NOT 混为一谈（`CONSTRAIN-1` 与 `JEV-5` 各自独立验收）。

### 2.4 Jev 工程纪律（权威纪律来源）

> 本节把 Jev 工程的权威纪律**显式写进本规范**。来源：TypeSafe AI 创始人 Diogo Almeida 关于 Jev 的公开工程说明，以及工程实践文章《Jev Engineering: Stop Using LLMs for Every Decision》。这些纪律不是「可选最佳实践」，而是本系统设计决策的**前置约束**。

**（一）三层权责划分（三层栈）**：一次智能体行为 SHALL 被拆分为三个**互不越权**的层次。

| 层 | 归属 | 职责 | 本系统对应 |
| --- | --- | --- | --- |
| **GENERATE（生成）** | LLM | 把上下文转化为**新内容**：研究、写作、规划、代码、解释、开放式综合 | 被路由的**目标模型**（`Model Gateway`） |
| **DECIDE（决策）** | JEV | 把状态转化为**类型化判断**：路由、打分、是否、重试、升级 | `TypeSafeJevAdapter` + `Selector` |
| **ENFORCE（执行/执法）** | CODE | 对**必须精确**的规则执法：权限、预算、重试上限、账户、写库、发布、删除、资金 | `ConstraintSelector` + `Model Gateway` 授权 |

> **判据**：需要**创造语言** → 用 LLM；需要**解释语义并从已知结果中选择** → 用 Jev；需要**服从精确不变量** → 用代码。三者 MUST NOT 相互替代。

**（二）置信度不是授权（本系统最危险的反模式）**：Jev 的置信度**只是路由信号**，MUST NOT 直接充当「执行许可」。

```
JEV JUDGES   →   CODE CHECKS POLICY   →   TOOL EXECUTES   →   TRACE RECORDS
```

即便 `conf = 0.99`，是否执行仍 SHALL 由 `ConstraintSelector` 的硬约束与策略开关裁定（`CONSTRAIN-1` `CONSTRAIN-3`）。

**（三）决策契约（question is part of the program）**：一个生产级 Jev 提问 SHALL 是一份**决策契约**，而非随意 prompt。契约字段与版本化见 `JEV-12`：

```
state fields · question instructions · option descriptions / rubric ·
fallback outcome · confidence thresholds · allowed action · escalation path · version
```

- **字段名帮助代码，instructions 帮助模型**：`safe_to_publish` 这类键名 **MUST NOT** 被视为对模型的指令；真正的规则 SHALL 写在 `instructions` 与 `criteria` 中（弱/强写法对比见 `design.md` §4.10）。
- **契约版本化**：决策契约 SHALL 与业务代码**独立版本化**（如 `ticket-router@3`），语义决策的变更 SHALL 像代码变更一样被评审、测试、可回滚（`JEV-12` `EXP-9`）。

**（四）三原语语义规则（防误用）**：

| 原语 | 用途 | MUST NOT 误用 |
| --- | --- | --- |
| **Choice** | 恰有一个选项胜出 | 菜单可能不完备时 MUST 提供逃生舱（`none` / `other` / `stop` / `escalate`），否则概率质量被强加到「最不错误」的答案上（`JEV-13`） |
| **Score** | 有序评分档（rubric） | MUST NOT 把档间值当作精确测量——`1.6` **不是**「80% 好」，而是落在自定义描述之间的位置（`JEV-13`） |
| **Noul** | 是/否概率 | `≈0.5` 表示**模型无法区分**，**不是**「中等风险」；需要低/中/高分级时 SHALL 改用 `Score`（`JEV-13`） |

**（五）状态工程（state engineering）**：Jev 只能判断你提供的状态。输入状态 SHALL 按功能分离，MUST NOT 把断言、指令、旧尝试与无关历史混成一团（`JEV-14`）：

```
GOAL / FACTS / ARTIFACTS / EVIDENCE / CONSTRAINTS / OPTIONS
```

> **边界诚实**：类型安全**约束输出形状，不保证语义正确**。Jev 无法破坏声明的 schema，但仍可能选出「合法的错误选项」。因此证据、阈值、测试与复核**仍然必需**（对应 §1.4 非目标与 G3）。

**（六）后果分级阈值**：阈值 SHALL 绑定到**动作后果等级**，而非只绑定模型输出。给内部备忘定级与发布公开声明 MUST NOT 共用同一个自动化阈值（`JEV-15`，细化 D7）。

**（七）决策凭据（decision receipt）**：系统 SHALL 保留**契约版本 + 状态引用 + 完整分布 + 阈值 + 路由 + 实际动作**，MUST NOT 只存胜出标签（`JEV-16`）。无凭据的决策不可复现、不可审计。

## 4. 关键决策与取舍

| # | 决策点 | 选项 | 选定 | 理由与代价 |
| --- | --- | --- | --- | --- |
| D1 | 决策层接入形态 | (a) 仅真实 Jev API (b) 仅本地重实现 (c) **真实 API 为主 + 可切换本地重实现** | **(c)** | 理由：生产必须真实调用 System One；但离线演示与零外部依赖场景需要本地确定性重实现兜底。代价：本地重实现与官方契约存在偏差（附录 F），必须显式登记且不得冒充官方机制 |
| D2 | 交付形态 | (a) 单文件自包含 (b) 前后端分离 (c) **前后端分离为主 + 单文件降级** | **(c)** | 理由：经验沉淀与结果确认回写必须有服务端；同时保留纯前端模式以便离线演示。代价：需维护两套数据通道，但共用同一逻辑层 |
| D3 | 前端框架 | (a) React/Vue (b) **原生 ES5 + IIFE** | **(b)** | 理由：单页少页签、无路由；框架运行时与 hydration 开销与「加载 < 3s」目标相悖。代价：自维护 DOM 重建与签名短路 |
| D4 | 3D 渲染 | (a) R3F (b) **Three.js 直操作 `Object3D`** | **(b)** | 理由：不需声明式组件树，直操作更贴近「每帧零分配」目标。代价：自研 Orbit 控制器 |
| D5 | 状态管理 | (a) Redux 本体 (b) **自实现 Redux 模式容器（~20 行）** | **(b)** | 理由：满足单一 state 树 + 纯 reducer + 订阅通知的实质要求，省运行时。代价：无中间件生态 |
| D6 | 路由可复现性 | (a) 完全确定性 (b) **负载感知 + 复位通道** | **(b)** | 理由：负载惩罚避免拥塞节点是设计意图。代价：同一 prompt 不同时刻可能选不同模型；需提供 `loadMap` 复位到 `baseLoad` 的可复现通道 |
| D7 | 置信度阈值 | (a) 全系统统一 (b) **按动作风险分级 + 演示取值** | **(b)** | 理由：官方要求阈值按动作风险分级且不给固定值。代价：需为每类动作单独标定，初期给演示取值（`0.82 / 0.60`）并标注待标定 |
| D8 | 结果呈现位置 | (a) 仅结果页签 (b) **内联 + 详情双通道** | **(b)** | 理由：需求明确要求「在 Prompt 输入框内直接呈现」。代价：需保证两处由同一 `record` 派生 |
| D9 | **经验回流的作用面** | (a) 改写能力画像 (b) 无界偏置 (c) **有界偏置 + 伪计数收缩** | **(c)** | 理由：(a) 让经验反推画像，静态标定失去意义；(b) 小样本下退化为「永远选历史胜率最高模型」。代价：收敛慢，需更多确认样本，但这正是保守性的体现 |
| D10 | **经验应用的可复现策略** | (a) 重放总用最新经验 (b) **档案钉住 `expVersion`** | **(b)** | 理由：不钉版本则历史档案不可复现，「档案可完整复现决策」失效。代价：需为每个经验版本保留先验快照，存储与回滚更复杂 |
| D11 | **结果确认的来源范围** | (a) 仅人工 (b) 人工 + 系统 (c) **人工 + 系统 + 隐式弱标签** | **(c)** | 理由：低置信转人工是低频事件，仅靠人工回填样本积累极慢；隐式行为（换模型重跑/重新生成/放弃）是唯一高频信号。代价：隐式信号语义模糊，须标注弱标签、权重低于人工，且不得单独构成劣化判定依据 |
| D12 | **阈值重标定建议的生效方式** | (a) 统计后自动生效 (b) **生成建议 + 人工批准后生效** | **(b)** | 理由：自动生效等于让统计噪声直接改写生产安全阀。代价：需人工介入，但 `EXP-10` 的自动校验与回滚仍为全自动 |
| D13 | **Jev 与 Selector 的权责** | (a) Jev 直接决定执行模型 (b) **Jev 推荐 + Selector 硬约束终裁** | **(b)** | 理由：Jev 的类型安全只约束输出形状，不保证业务正确性；硬约束（预算/合规/健康）必须独立于模型推荐。代价：需维护两段式决策链与可解释的淘汰理由 |
| D14 | **五问调用方式** | (a) 逐题串行 (b) **单请求内并行打包 fan-out** | **(b)** | 理由：批量调用相较逐题在成本与延迟上有数量级优势，是满足决策成本占比的前提。代价：需适配一次性批量响应结构 |
| D15 | **三层权责边界** | (a) 让 Jev 同时生成与决策 (b) **GENERATE=LLM / DECIDE=JEV / ENFORCE=CODE 严格分层** | **(b)** | 理由：生成与决策混在同一调用是智能体成本与不可控的根因；Jev 不生成文本正是其成为快速可组合决策层的前提。代价：需维护三层接口与边界测试 |
| D16 | **置信度是否可充当执行授权** | (a) 高置信直接执行 (b) **置信度仅为路由信号，执行由代码策略裁定** | **(b)** | 理由：把概率判断升级为无界授权是最危险的反模式（「confidence becomes permission」）。代价：即使高置信也须过策略引擎，链路更长 |
| D17 | **决策契约形态** | (a) 随意 prompt (b) **8 字段决策契约 + 独立版本化** | **(b)** | 理由：语义决策是生产逻辑，须像代码一样评审 / 测试 / 回滚。代价：契约维护与版本管理成本 |
| D18 | **阈值绑定对象** | (a) 统一绑定模型输出 (b) **绑定动作后果等级** | **(b)** | 理由：路由内部备忘与发布公开声明不应共用自动化阈值。代价：须为每类动作标定后果等级 |
| D19 | **状态输入组织** | (a) 一大段对话文本 (b) **按功能分离的 6 段状态** | **(b)** | 理由：模型只能判断你给的状态；混杂状态会让合法输出仍然语义错误。代价：接入层须做状态规范化 |

## 5. 影响面与风险

### 5.1 影响面

| 层面 | 影响 |
| --- | --- |
| 前端 | 新增内联结果区、真实事件流消费、经验复核回写入口；布局矩阵断言需更新 |
| 后端 | 新增 Jev Adapter、Selector、Experience Store、事件流服务；经验版本管理 |
| 数据 | 新增 `ExperienceEntry` / `expVersion` / `priorSnapshot` 存储；档案 schema 扩展 |
| 运维 | 新增 Jev 健康监控、降级开关、经验版本回滚入口、劣化告警 |

### 5.2 风险与缓解

| # | 风险 | 等级 | 缓解 |
| --- | --- | --- | --- |
| R1 | 真实 Jev 处于 early access，可用性/配额不确定 | 高 | 显式降级路径 + shadow mode + 可切换本地重实现兜底 |
| R2 | 经验回流引入选型漂移，历史不可复现 | 中 | 钉 `expVersion` + 先验快照 + 可复现通道 |
| R3 | 小样本噪声污染先验 | 中 | 伪计数收缩 + 最小样本守卫 + shadow 模式 |
| R4 | 正反馈导致选型固化 | 中 | 有界偏置 + 反固化断言 |
| R5 | 模型画像升级后旧经验误导 | 中 | `profileVersion` 变更强制经验失效 |
| R6 | 隐式弱标签语义模糊 | 低 | 弱标签降权 + 不得单独触发劣化判定 |
| R7 | 硬约束与 Jev 推荐冲突导致不可解释 | 低 | 固定约束顺序 + 确定性错误码 + 审计摘要 |
| R8 | 置信度被当作执行授权（最危险反模式） | 高 | 三层权责隔离：`JEV JUDGES → CODE CHECKS POLICY → TOOL EXECUTES`；执行权恒在代码（`CONSTRAIN-1` `CONSTRAIN-3` D16） |
| R9 | 单阈值控制全部后果等级 | 中 | 阈值绑定动作后果等级矩阵，分级标定（`JEV-15` D18） |
| R10 | 选项菜单过期 / 无逃生舱导致强制错选 | 中 | 选项集由实时状态重建 + `Choice` 强制逃生舱（`none`/`other`/`stop`/`escalate`）（`JEV-13`） |
| R11 | 决策无凭据，不可复现 / 不可审计 | 中 | 决策凭据保留契约版本 + 状态引用 + 完整分布 + 阈值 + 路由 + 实际动作（`JEV-16` `ARCHIVE-1`） |

## 6. 验收总则

本变更 SHALL 以「**闭环是否合上**」为核心验收判据（详见 `spec.md` §0.7）：仅实现经验记录与统计、而未实现回流应用与自动校验回滚者，SHALL 判定为**开环**，不得对外宣称具备经验积累能力。
